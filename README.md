# АэропортБД

Учебная система управления базой данных аэропорта.  

## Технологии

| Слой | Стек |
|---|---|
| СУБД | PostgreSQL 16 (Docker-образ `postgres:16-alpine`) |
| Веб-интерфейс | Python 3.9+, Streamlit ≥ 1.43 |
| Адаптер БД | psycopg2-binary ≥ 2.9 |
| Контейнеризация | Docker Compose |

---

## Структура проекта

```
airport_db/
├── docker-compose.yml        # Поднимает контейнер PostgreSQL
├── .env                      # Переменные окружения для PostgreSQL
├── sql/
│   ├── 01_schema.sql         # DDL: таблицы, триггер, ограничения
│   ├── 02_users.sql          # Создание пользователей БД и назначение прав
│   └── 03_data.sql           # Тестовые данные (авиакомпании, рейсы, билеты …)
└── app/
    ├── app.py                # Streamlit-приложение (весь UI и SQL-запросы)
    └── requirements.txt      # Python-зависимости
```

## Схема базы данных

База содержит **7 таблиц**, связанных внешними ключами:

```
airline ──< aircraft ──< flight ──< ticket >── passenger
                            └──< crew_assignment >── employee
```

| Таблица | Ключ | Описание |
|---|---|---|
| `airline` | `iata_code` CHAR(2) PK | Авиакомпании: код IATA, название, страна |
| `aircraft` | `tail_number` PK | Самолёты: модель, вместимость, год выпуска, авиакомпания |
| `flight` | `flight_id` SERIAL PK | Рейсы: номер, маршрут, время вылета/прилёта, статус |
| `passenger` | `passenger_id` SERIAL PK | Пассажиры: ФИО, паспорт (UNIQUE), дата рождения, телефон |
| `ticket` | `ticket_no` VARCHAR PK | Билеты: место, класс, цена, дата покупки |
| `employee` | `employee_id` INTEGER PK | Сотрудники экипажа: ФИО, должность, дата найма |
| `crew_assignment` | `(flight_id, employee_id)` PK | Назначения экипажа на рейсы (M:M) |

### Ограничения целостности

- `CHECK` на статус рейса: `'по расписанию'`, `'задержан'`, `'отменён'`, `'выполнен'`
- `CHECK` на класс обслуживания: `'эконом'`, `'бизнес'`, `'первый'`
- `UNIQUE (flight_id, seat_no)` — одно место нельзя продать дважды
- `UNIQUE passport_no` — дублирующиеся паспорта недопустимы
- Триггер `trg_check_seat_availability` — блокирует продажу билета при отсутствии свободных мест

## Ролевая модель безопасности

Реализована средствами PostgreSQL (принцип минимальных привилегий):

| Пользователь БД | Роль в приложении | Привилегии |
|---|---|---|
| `admin_user` | Администратор | `ALL` на все таблицы; `CREATEDB`, `CREATEROLE` |
| `dispatcher_user` | Диспетчер | `SELECT` на всё; `INSERT/UPDATE/DELETE` на `flight`, `crew_assignment`; `UPDATE` на `aircraft` |
| `cashier_user` | Кассир | `SELECT` на `flight`, `passenger`, `ticket`; `INSERT` на `passenger`, `ticket`; `UPDATE (phone, passport_no)` на `passenger` |

## Функциональность приложения

### Страницы

| Страница | Доступ | Описание |
|---|---|---|
| Главная | Все | Метрики по таблицам, описание прав роли, описание БД |
| Таблицы | По роли | Постраничный просмотр таблиц |
| Запросы | По роли | 13 параметрических SQL-запросов |
| Отчёты | По роли | Сводные отчёты с визуализацией (bar chart) |
| Управление | По роли | Добавление/изменение данных через формы |
| Безопасность | Только Администратор | Матрица прав, просмотр DDL, проверка привилегий |

### 13 предустановленных запросов

1. Список пассажиров конкретного рейса
2. Расписание рейсов на дату
3. Рейсы конкретной авиакомпании *(недоступно Кассиру)*
4. Количество свободных мест на рейсе
5. Экипаж конкретного рейса *(недоступно Кассиру)*
6. Задержанные и отменённые рейсы за период
7. История использования самолёта за период
8. Средняя цена билета по классам обслуживания
9. Топ-5 пассажиров по суммарным расходам
10. Рейсы со свободными местами
11. Количество рейсов по статусам
12. Пассажиры без отчества (иностранные граждане)
13. Сотрудники без назначений на рейсы *(недоступно Кассиру)*

### Отчёты

- **Загрузка рейсов** — вместимость, продажи, процент загрузки, выручка
- **По сотрудникам** — стаж, количество рейсов за период *(Диспетчер, Администратор)*
- **По авиакомпаниям** — парк самолётов, выполненные рейсы, выручка *(Диспетчер, Администратор)*

## Быстрый старт

### Требования

- [Docker](https://docs.docker.com/get-docker/) и Docker Compose (входит в Docker Desktop)
- Python 3.9 или новее
- pip

### 1. Запустить базу данных

```bash
# Из корня репозитория
docker compose up -d
```

Docker Compose поднимет контейнер `airport_postgres` на порту **5432**.  
При **первом запуске** PostgreSQL автоматически выполнит скрипты из папки `sql/` в алфавитном порядке:
`01_schema.sql` → `02_users.sql` → `03_data.sql`.

Убедитесь, что база готова к подключениям:

```bash
docker compose ps          # статус контейнера — "healthy"
docker compose logs --tail=20 postgres   # лог инициализации
```

### 2. Установить Python-зависимости

```bash
cd app
pip install -r requirements.txt
```

Если используете виртуальное окружение:

```bash
python -m venv .venv
source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

### 3. Запустить Streamlit-приложение

```bash
# Из папки app/
streamlit run app.py
```

Приложение откроется по адресу **http://localhost:8501**.

### 4. Войти в систему

На странице входа выберите роль и введите пароль:

| Роль | Пароль |
|---|---|
| Администратор | `admin_pass_2024` |
| Диспетчер | `dispatcher_pass_2024` |
| Кассир | `cashier_pass_2024` |

> Пароли также отображаются прямо на странице входа в разделе «Тестовые пароли для демонстрации».

## Управление контейнером

```bash
# Остановить контейнер (данные сохраняются в Docker-томе pg_data)
docker compose stop

# Удалить контейнер И все данные (полный сброс БД)
docker compose down -v

# Пересоздать БД с нуля (повторное выполнение SQL-скриптов)
docker compose down -v && docker compose up -d
```

## Переменные окружения (.env)

| Переменная | Значение по умолчанию | Описание |
|---|---|---|
| `POSTGRES_DB` | `airport_db` | Имя базы данных |
| `POSTGRES_USER` | `postgres` | Суперпользователь PostgreSQL |
| `POSTGRES_PASSWORD` | `postgres_root_2024` | Пароль суперпользователя |
| `PGPORT` | `5432` | Порт PostgreSQL |

Приложение также читает `DB_HOST` и `DB_PORT` из переменных окружения (по умолчанию `localhost:5432`).

psql -h localhost -p 5432 -U postgres -d airport_db
